# 通用去 AI 味

语言规则直接沿用 `deslop-article` 的 L1–L4，移除公众号专用的标题、导读、排版、配图规范和多代理审稿流程。

## 1. 按顺序执行四份语言清单

1. 读取全文和用户约束。
2. 读取并执行 [L1：禁句、空话与中文表达](references/language-pass-1-cut-translation.md)。
3. 重读当前文本，执行 [L2：主语、动词、术语和指代](references/language-pass-2-subject-terms.md)。
4. 重读当前文本，执行 [L3：标题、开场、结尾与判断解释](references/language-pass-3-framing-voice.md)。
5. 重读当前文本，执行 [L4：段落、加粗、Markdown 与 alt](references/language-pass-4-presentation.md)。
6. 通读修改处及其相邻段落，核对原意、事实、指代和衔接。

按文本实际存在的部分执行；没有标题、开场、结尾、图片或 Markdown 时跳过对应项，不额外补齐。

## 2. 全程保留事实与原有用途

- 不引入未证实事实，不改数字、单位、比较对象、因果强度和引用原意。
- 数字和修饰对象成对保留，关系、时间跨度、责任归属不漂移，不把排除关系升级成肯定事实。
- 不新增“我”，不虚构个人经历、情绪或矛盾来制造人味；原文真实的第一人称和立场保留。
- 代码、URL、专有名词、真实姓名、引语和承诺条款按原意保护；转述不得冒充直接引语。
- 不以词频、句长、段长或标点数量单独判错，不设压缩比例，不为修改而修改。
- 沿用用户要求的文体和固定格式；邮件称呼、行动请求、方案下一步、模板占位符等按实际用途保留。
- 只做命中问题的定点修改，未命中的段落保持不动；不擅自改主线或重构全文。

## 3. 按用户要求交付

- 用户要求去 AI 味、润色、精简或改写时，直接给改后文本；指定文件时修改该文件。
- 用户只要求审查、给意见或不要改文件时，只给带位置的问题与建议。
- 默认不附审稿报告、台账或修改过程；需要核实或无法安全处理的内容单独简短说明。
